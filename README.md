# 치과데이터랩 · 로컬 개발 v0.7.0

전국 치과 공공데이터 **리포트 + 조건 검색** 서비스입니다. 인수인계 v0.1의 정적 생성 방식과 19,681곳의 원자료를 이어서 개발합니다. Node.js 20 이상으로 실행하며 외부 npm 패키지·API 키·DB는 필요하지 않습니다.

## 실행

이 폴더에서:

```sh
npm run dev
```

**http://127.0.0.1:4173/** 을 엽니다. 첫 빌드가 끝난 뒤 화면이 나옵니다. `src/`, `scripts/`, `data/`를 저장하면 자동으로 다시 빌드하며, 완료 후 브라우저를 새로고침합니다. 빌드 실패 시 마지막 정상 화면을 유지합니다. `Ctrl+C`로 종료합니다.

- 다른 포트: `PORT=4174 npm run dev`
- Mac: `미리보기_실행.command`를 실행해도 같은 개발 서버가 켜집니다.
- 개발 결과는 `.dev-dist/`에 저장됩니다. `dist/`와 원본 인수인계는 보존합니다.
- `file://` 대신 로컬 HTTP 주소를 사용하세요.

## 빌드와 검사

```sh
npm run build
npm test
npm run preview
```

`npm test`는 집계·다운로드·로컬 서버·자동 재빌드 검사 후, 모든 생성 HTML의 링크·구조화 데이터·noindex·데이터 정합성을 검사합니다. 빠른 코드 검사만 할 때는 `npm run test:unit`, 기존 빌드의 전체 정적 검사만 할 때는 `npm run test:site`를 사용합니다.

## 네이버 업체 작성 안내 수집

네이버를 조사할 때 홈의 연락처·진료시간·길안내·실제 채널 주소와 정보 탭의 소개·대표키워드·예약/방문 안내·편의·주차·결제를 함께 확인합니다. 소개/길안내의 펼치기를 열고 마지막 문장까지 확인해야 하며, 접근성 텍스트가 중간에서 잘리면 화면으로 남은 구간을 대조하거나 미완료로 기록합니다.

업체 소개에 포함된 예약문구·휴진·의료진 약력은 소개 원문에 보존합니다. 실제로 별도 표시된 항목만 별도 필드로 기록하며, 문장을 추측해 분해하거나 다른 치과에 복사하지 않습니다. 원문별 출처·관찰일을 남기고 연도가 없는 날짜나 업체의 경력·전문의 주장을 공공자료 값으로 변환하지 않습니다. 현재 수집량은 홈페이지에서 공개하며, 방문자 리뷰 본문은 후속 단계입니다.

## 발굴한 홈페이지 후속 수집

`npm run collect:linked-homepages`는 기관 페이지의 실제 연결로 발견한 홈페이지 중 아직 시도하지 않은 주소를 추려 본문과 외부 채널 링크를 수집합니다. 원자료의 신고 홈페이지가 비어 있어도 이 단계에 들어갑니다. 이전 요청·수동 본문 확인·접근 실패 URL은 재요청하지 않으며, 자동 추출 링크는 후보 상태로 유지합니다. `node scripts/prepare-discovered-homepages.mjs --dry-run`으로 새 대상 수만 확인할 수 있습니다. 실행 전 준비한 입력과 결과는 각각 `data/research/discovered-homepage-seeds.json`, `data/assets/discovered-homepages.json`에 남습니다.

이번 후속 수집은 25주소 중 22본문, 실제 연결 50개를 확인했습니다. 이는 URL이 아직 없는 전국 기관의 검색까지 자동 완료한 것이 아닙니다.

## 전국 지도 후보 수집 재현

`python3 scripts/discover-national-naver.py --rematch`는 저장된 관찰만 재대조합니다. 네트워크 요청은 하지 않습니다. 수집 도중 중단된 작업은 `--resume`으로 미시도 지역만 이어갈 수 있고, 접근 차단 기록이 있는 작업은 재개하지 않습니다. 옵션 없는 실행은 새 공개 디렉토리 조사를 시작합니다.

수집기는 `/regions`에 실제 연결된 시군구 페이지를 순차 요청하고, 기관명·주소·실제 지도 링크만 저장합니다. 네이버 대상 페이지는 요청하지 않으며, 이 자료에는 네이버 진료시간이 없습니다. `npm run test:naver-discovery`로 오귀속 방지 회귀를 검사합니다. 최신 단계별 현황과 미완료 목록은 빌드할 때 관찰 자료에서 다시 생성됩니다.
